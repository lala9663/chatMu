# 업무 정의서 - 개요

## 제품 한 줄 정의

업무시간에 친구들끼리 지금 듣는 노래를 실시간으로 공유하고, 그걸 소재로 소소하게 떠드는 소셜 음악 서비스.

## 문제 정의

- 경쟁자는 다른 음악 앱이 아니라 **업무시간의 카톡 잡담**이다. 음악은 잡담의 소재.
- 한국 직장인은 멜론/유튜브뮤직/스포티파이/애플뮤직으로 플랫폼이 파편화되어 있어, "지금 이 노래 들어봐"가 링크 하나로 통하지 않는다.

## UX 지향: 조용한 존재감

- 앰비언트 피드 — 열어두고 가끔 보는 화면.
- 알림 최소화 — 기본 OFF, 직접 추천받았을 때만.
- 10초 단위의 저마찰 상호작용 — 이모지 반응, 한 줄 채팅.

## 성공 기준

| 지표 | 기준 |
|---|---|
| 핵심 검증 | 친구 그룹 1개가 업무시간에 **3주 이상 자발적으로 켜두는가** |
| 보조 지표 | 방 내 일일 반응/채팅 수, 추천곡 실제 청취 전환 |

## 재생 감지 커버리지 (확정 스코프)

| 상황 | 감지 방법 | 자동 |
|---|---|---|
| Spotify (모든 기기) | 서버 폴링 워커 (Spotify Web API) | ✅ |
| Android + 모든 음악앱 | NotificationListenerService (Kotlin 네이티브 모듈) | ✅ |
| iPhone + Apple Music | MPMusicPlayerController (Swift 네이티브 모듈) | ✅ |
| iPhone + 유튜브뮤직/멜론 | 미지원 (추후 공유 시트 확장 고려) | — |

## 프라이버시 원칙

상시 공유 서비스이므로 **공유 OFF 상태에서 데이터가 새는 버그는 크리티컬**로 취급한다. 잠수 모드/곡 숨기기 관련 코드는 항상 최우선으로 동작을 보장한다.
